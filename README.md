# Мой рацион — трекер (PWA)

Своё приложение для учёта калорий и БЖУ на набор массы. Работает офлайн, ставится
на телефон и ПК как иконка, синхронизируется между устройствами через твой
собственный бесплатный Supabase. Никаких подписок, рекламы и чужих аккаунтов.

- **План** (меню, рецепты, закупка, траектория) остаётся в артефакте.
- **Это** — только ежедневный трекинг с историей и синком.

---

## 🔑 Ключи и переменные окружения (важно)

**Ключи в репозиторий не коммитятся.** `config.js` в `.gitignore`.

- **В проде (Netlify)** `config.js` генерируется при сборке скриптом `scripts/gen-config.js`
  из переменных окружения. USDA-ключ в клиент не попадает вообще — поиск идёт через
  серверную функцию `netlify/functions/usda.js`.
- **Локально** копируешь `config.example.js` → `config.js` и вписываешь ключи (файл
  не уедет в гит).

**Переменные окружения на Netlify** (Site settings → Environment variables):

| Переменная | Значение |
|---|---|
| `SUPABASE_URL` | Project URL из Supabase |
| `SUPABASE_ANON_KEY` | Publishable-ключ (`sb_publishable_…`) |
| `USDA_API_KEY` | ключ FoodData Central (только на сервере, в браузер не отдаётся) |

**Настройки сборки** уже заданы в `netlify.toml` (поля в UI можно оставить пустыми):
build command `node scripts/gen-config.js`, publish `.`, functions `netlify/functions`.

> Publishable-ключ Supabase всё равно окажется в клиенте (так работает Supabase SDK,
> доступ закрыт RLS — это безопасно), но **из репозитория он убран**. USDA-ключ не
> виден нигде в браузере.

**Если `config.js` уже был закоммичен** — убери его из отслеживания (файл на диске
останется):

```bash
git rm --cached config.js
git commit -m "chore: untrack config.js (keys move to env)"
```

Ключи из старого коммита остаются в истории git. USDA-ключ был засвечен —
**перевыпусти его** на fdc.nal.usda.gov и положи новый только в env Netlify.
Publishable-ключ Supabase перевыпускать не нужно (он публичный по дизайну).

## 1. Запустить локально (проверить, что работает)

Скопируй `config.example.js` в `config.js`, впиши ключи Supabase (и, для локального
поиска USDA без Netlify, `USDA_API_KEY`). Затем любой статический сервер из папки:

Нужен любой статический сервер. Из папки `ration-tracker`:

```bash
python -m http.server 5173
```

Открой `http://localhost:5173`. Пока ключи не вписаны — приложение работает
**локально** (данные в браузере), синка нет. Этого достаточно, чтобы потыкать.

> Просто открыть `index.html` двойным кликом (file://) — не годится: не работают
> service worker и часть браузерных API. Только через `http://`.

## 2. Включить синхронизацию телефон↔ПК

### 2.1 Завести Supabase (бесплатно, без карты)
1. Зайди на **supabase.com** → Sign up (можно через GitHub/Google).
2. **New project** → любое имя, задай пароль базы (запиши), регион ближе к тебе.
3. Дождись создания (~1–2 мин).

### 2.2 Создать таблицы
1. В проекте: **SQL Editor** → **New query**.
2. Вставь всё содержимое `schema.sql` из этой папки → **Run**.

Создаются две таблицы:
- `tracker_state` — **личный** дневник: у каждого пользователя своя строка, чужое
  недоступно (Row Level Security).
- `shared_products` — **общая** база продуктов: то, что добавил один, видят все;
  удалять и править может только автор. В приложении такие продукты сгруппированы
  по **логину автора** (часть email до `@`).

> Приватность: логин автора виден всем пользователям сервиса. Полный email не
> показывается и не хранится в этой таблице — только его первая часть. Если сервис
> не только для своих, имей это в виду.

Локальные данные тоже разделены по аккаунтам: на одном устройстве каждый вход
получает своё хранилище, дни и норма не смешиваются.

### 2.3 Вписать ключи
1. **Project Settings → API Keys**.
2. Скопируй **Project URL** и **Publishable key** (начинается на `sb_publishable_…`;
   в старых проектах он называется `anon`).
3. Открой `config.js` и вставь их:
   ```js
   window.RATION_CONFIG = {
     SUPABASE_URL: "https://xxxx.supabase.co",
     SUPABASE_ANON_KEY: "sb_publishable_..."   // ← Publishable key
   };
   ```
> **Бери именно Publishable key.** Он публичный по дизайну — его видно в браузере, это
> нормально: доступ к чужим данным закрыт правилами Row Level Security из `schema.sql`.
>
> ⚠️ **Secret key (`sb_secret_…`, бывший `service_role`) сюда НЕ вставляй никогда.** Он
> обходит всю защиту и, попав в браузер, откроет твою базу кому угодно. Он только для
> сервера — а у этого приложения сервера нет.

### 2.4 Проверить
Перезапусти локальный сервер, открой приложение → кнопка **«Войти / синк»** →
**Зарегистрироваться** (email + пароль). После входа данные уедут в облако.

> По умолчанию Supabase может требовать подтверждение почты. Если вход не проходит:
> **Authentication → Providers → Email** → выключи *Confirm email* (для личного
> использования ок), либо подтверди письмо из ящика.

## 3. Выложить в интернет (чтобы открывать с телефона)

Локальный сервер виден только на этом ПК. Чтобы заходить с телефона — залей папку
на любой бесплатный статический хостинг. Проще всего перетаскиванием:

- **Cloudflare Pages** (`pages.cloudflare.com` → Create → Direct Upload) — перетащи
  папку, получишь адрес вида `https://ration.pages.dev`.
- или **Netlify Drop** (`app.netlify.com/drop`) — то же самое перетаскиванием.

Открой полученный адрес на телефоне и на ПК, войди одним аккаунтом — данные общие.

### Поставить как приложение (иконка на экране)
- **Android/Chrome**: меню ⋮ → «Установить приложение».
- **iPhone/Safari**: «Поделиться» → «На экран Домой».
- **ПК/Chrome**: значок установки в адресной строке.

## Как хранятся данные и про синк
- Всегда есть **локальная копия** в браузере (работает офлайн, ничего не теряется).
- Если вошёл — та же копия лежит в **твоём** Supabase и подтягивается на любом
  устройстве. Модель простая: **кто последним сохранил, тот и прав** (last-write-wins).
  Для одного человека это ок; не редактируй один и тот же день одновременно на двух
  устройствах, иначе одна из правок перезапишется.
- Кнопки **Экспорт/Импорт** — резервная копия и ручной перенос в JSON, работают и
  без облака.

## Обновление
Поменял файлы — если включён хостинг, перезалей папку. Локально хватает обновить
страницу. При изменении `app.js`/`styles.css` подними версию `CACHE` в `sw.js`
(например `ration-v2`), иначе браузер отдаст старое из кэша.

## Файлы
| файл | зачем |
|---|---|
| `index.html` | разметка |
| `styles.css` | оформление (свет/тёмная тема) |
| `app.js` | вся логика: трекер, история, синк |
| `config.js` | твои ключи Supabase (единственное, что надо заполнить) |
| `schema.sql` | таблица + правила доступа для Supabase |
| `manifest.webmanifest`, `sw.js`, `icon.svg` | PWA: установка и офлайн |
